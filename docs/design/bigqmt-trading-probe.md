  后者可以包含非数字字符，不能转整数。

  样本 55 暂按 UNKNOWN 保留，m_nOpType 的特殊值也原样保留。

## 运行

1. 在完整 QMT 新建独立 Python 策略，粘贴脚本。
2. 在终端中的脚本副本填写 `SIM_ACCOUNT_ID`，使用模拟账户。
   `SIM_ACCOUNT_TYPE` 默认 `STOCK`，与参考股票账户调用一致；其他账户类型按终端实际配置填写。
   账号只保留在本地副本，不回传、不写入仓库。
3. 正常启动策略。出现 `trading_read_probe_complete` 后停止。
4. 返回带 `QMT_RPYC_TRADE_PROBE` 的输出。空持仓、空委托也可直接返回日志。

本脚本可与财务探针分别运行。它兼容 Python 3.6，不需要安装 qmt-rpyc。

## 调用与输出边界

只调用三次 `get_trade_detail_data(account, type, kind)`，kind 分别为 ACCOUNT、POSITION、ORDER。
不调用 passorder、cancel、can_cancel_order、get_last_order_id 或 get_value_by_order_id。
这些函数仅检查入口和可提取的参数名称，不把最近订单当作本次提交的关联依据。

每类结果至多展示两条记录，每条最多 120 个原生 m_ 字段，只输出类型、是否有值、
字符串长度与是否纯数字。白名单内的账户类型、委托状态、报价类型、方向等整数枚举保留数值，
以便验证状态转换。账号、证券代码、订单号、金额、备注、时间原文均不输出。
候选订单标识只报告两字段的文本是否相同，不推断它们可互换或已能用于撤单。

原生异常和字段读取异常仅输出错误类型，不带可能含本地信息的异常文本。
空结果证明调用返回，不能证明其记录字段符合公共模型；本轮也不证明下单返回值或撤单结果语义。


## 协议 4：已实现的交易接口

用户确认交易恢复后，五项交易操作已接入。服务与 GBK 策略须一起升级至私有协议 4，
公共契约仍为 v3。支持 STOCK 账户，使用账户实测字段 m_nBrokerType=2 校验；
不能由此识别模拟或真实账号，调用方必须选择正确账号。启动、安装和只读检查不下单。

资产字段使用 m_dAvailable、m_dFrozenCash、m_dStockValue、m_dBalance；持仓直接映射
实测数量、开仓价、市值。订单 order_id 是原始 m_strOrderRef（保留前导零），
exchange_order_id 是 m_strOrderSysID。源报价枚举未验证，pricing 保持 UNKNOWN，
source_price_type 原样返回；未知操作类型同样不猜测买卖方向。

下单使用 passorder 的 11 参数形式：23/24、1101、账号、代码、11/5、价格、数量、
策略名、quickTrade=2、关联备注、ContextInfo。仅支持沪深六位代码。
correlation_ref 为空时生成 qp 开头的随机备注；非空时保留调用方值，并检查已存在委托与
当前桥实例内尝试记录，拒绝复用。实例内最多保留 10,000 个尝试，不淘汰后重放。
重启不能当作重试授权，调用方须先核对原订单。

原生返回只记录而不映射订单号。外部服务最多观察 10 秒，用唯一备注、账户、代码、
数量及限价核对新增委托引用；观察不占用 QMT 回调线程。匹配订单为废单时返回 Rejected，
其余返回 Submitted(ref)，不表示已成交。缺失、冲突、断线、解析失败或超时均明确 unknown，
不重新提交。调用前错误是 not_executed。原生调用仍不能强制中断。

撤单按调用方提供的引用或市场+柜台编号精确找到一条委托，再使用 get_value_by_order_id
核对身份并检查 can_cancel_order；仅传该 SysID 给 cancel。只接受原生 bool 返回，
True 表示请求被接受，不表示最终撤销；其他类型视为 unknown，False 表示未接受。
布尔结果采用参考项目语义，仍需当前实机确认。debug 保持只读，交易从类型化接口调用。

本地合成测试不替代实际下单和撤单验收。安装包不会自动执行先前确认的模拟单。
