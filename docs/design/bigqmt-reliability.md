# 完整 QMT 策略桥的可靠性要求

用户将内部通信选型交由本项目决定，要求稳定可靠。已选择 Windows 同机命名管道，
外部远程客户端继续使用现有 RPyC。以下是设计与验收要求，不代表已经通过生产验收。

## 分工与边界

外部 qmt-rpyc 服务仍独立于 QMT 策略启动。策略未运行或连接失效时，RPC 协商、健康查询
仍然可用，需要策略的操作明确失败。内置策略兼容 Python 3.6.8，外部服务保留既有运行环境。
内部传输采用有大小限制的 JSON 消息，包含协议版本、桥实例标识、请求标识与操作名，
校验响应关联关系；策略不接收任意函数名、代码执行或 pickle。

生产实现将管道 I/O 与 QMT 业务执行分离：传输负责接收和发送，策略回调只领取有界队列
中的业务请求。线程调度以实际部署证据确定；不能把必须在策略线程运行的交易查询搬到后台，
也不能未经验证把所有行情访问强制串行。需要分别验证后台纯 I/O 线程和各类业务调用。

底层 QMT 调用可能阻塞，线程无法强制取消原生调用；进程崩溃也不能由管道恢复执行结果。
客户端等待超时、I/O 取消和业务操作被取消是不同的事实。

## 必须满足的行为

| 场景 | 要求 |
|---|---|
| 连接、写入或读取迟迟不完成 | 单调截止时间覆盖整个传输过程；策略线程不执行阻塞管道读写。 |
| 写入失败或响应丢失 | 不根据写入错误推断请求未执行；有副作用请求不自动重发，无法证明未执行则保留 unknown。 |
| 请求在队列中过期 | 执行前检查截止时间；尚未执行的过期请求明确拒绝。取消标记与取出执行之间需要确定的状态转换。 |
| 下单后未取得真实编号 | 不返回虚构编号或假拒绝；通过回调/查询可靠关联，截止时间后返回未知结果。 |
| 策略或服务重启 | 新实例使用新世代；旧实例响应不可复用，不恢复或重放旧的修改请求。 |
| 迟到、重复、错误关联响应 | 丢弃或明确报错，不能作为其他请求的结果。 |
| 慢消费者、请求洪峰、大结果 | 连接、队列、单帧和在途内存有上限，过载明确失败；超大结果不得悄悄截断。 |
| 超时后清理原生 I/O | 取消后等待完成，再释放缓冲区、OVERLAPPED 和句柄；不能把发出取消请求视为完成。 |
| SDK 返回缺字段或不匹配的数据 | 沿用公共字段与错误语义，不补造默认值；单项缺失保留逐项错误。 |

不宣称跨崩溃的 exactly-once。断线重连用于接受未来的新请求，不能借恢复连接重放未知结果的请求。
公共合约本来不保证下载数据覆盖完整或行情新鲜；新桥也不能扩大此承诺。

## 实现依据

参考项目存在同步写入不受读取超时约束、写错误自动重发、WinAPI 原型声明不完整等问题，
因此借鉴其部署经验，不直接复制传输实现。
Windows 命名管道异步 I/O 需要带 OVERLAPPED 的句柄和独立操作结构；
`PIPE_NOWAIT` 不能替代此机制。取消调用不等待操作结束，相关缓冲区与结构必须保留至完成。
依据：[Microsoft 异步管道 I/O](https://learn.microsoft.com/en-us/windows/win32/ipc/synchronous-and-overlapped-input-and-output)、
[CancelIoEx](https://learn.microsoft.com/en-us/windows/win32/api/ioapiset/nf-ioapiset-cancelioex)。

## 验证阶段

1. 当前[跨进程探针](bigqmt-pipe-probe.md)：只回显合成数据，在真实 QMT 中验证异步 I/O、
   定时轮询、消息相关性、大消息、断开后新连接以及慢消费者下其他连接能否继续。
2. 生产通信层的确定性测试：取消与完成竞态、排队截止与执行竞态、迟到响应、部分写入、
   桥实例切换、半帧断线、全部队列满、超过帧长上限、请求到达后故意丢弃响应。
   以合成修改操作计数器检查不重发，不使用真实交易验证这些故障场景。
3. Windows 压力与资源测试：并发请求、持续连接创建关闭、服务/策略停止与重启、句柄数和
   线程数稳定、所有工作线程在限定时间内退出。单次短探针通过不等于长期稳定。
4. 业务验收：数据映射、兼容下载任务与交易回调协调，分别验证结果与错误语义。

跨进程 echo 探针已由用户实机运行，列出的检查全部通过；慢读路径产生预期写超时，
停止时没有保留未完成的句柄。该证据覆盖探针场景，不涵盖生产协议、长期压力与业务执行。
探针协议与生产协议分开，探针不得用于业务调用。
