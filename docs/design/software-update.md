# 本机软件升级与进程管理

客户端与服务端共用本机升级流程，一个 Python 环境管理一个服务实例。本文记录当前机制及其选择理由；安装和命令用法见 [README](../../README.md)，配套版本见[版本规则](../versioning.md)。

## 选择与代价

升级当前 Python 环境中的 qmt-rpyc，服务采用当前用户的后台进程管理。此方案延续个人 QMT 部署，避免额外 Windows 系统服务与版本环境切换；代价是不提供自动回滚、开机自启或崩溃自动拉起。多实例使用不同虚拟环境。

本机管理通道独立于业务 RPC，维护修复不要求旧 RPC 先恢复。升级先排空并停止服务，安装后保持停止并输出下一步命令；不自动启动，以支持显式降级到不具备新管理机制的旧版本。新进程验证包版本和命令加载，QMT 连接或 RPC 就绪不作为升级成功条件。

## 命令行为

| 命令 | 行为 |
|---|---|
| `qmt-rpyc-client update` | 升级本机环境；该环境有受管理服务实例时协调停机 |
| `qmt-rpyc-server update` | 排空并停止本环境服务，升级包并保留服务端依赖 |
| `update --pre` | 选择 TestPyPI 预发布目标，第三方依赖仍从 PyPI 获取 |
| `update --version <版本>` | 安装精确版本，允许显式降级，来源由目标是否为预发布决定 |
| `qmt-rpyc-server start` | 后台启动，确认 RPC 就绪 |
| `start --foreground` | 前台调试运行 |
| `stop` | 拒绝新请求，等待在途工作完成并退出 |
| `restart` | 停止后按原配置重新启动 |
| `status` | 独立报告进程、RPC 与 QMT 连接状态 |

默认升级到 PyPI 最新稳定版，不自动降级。允许跨 MINOR 升降级，并提示其他端及 BigQMT 策略的配套要求。没有版本变化则不停止服务。editable 安装拒绝 update，源码通过 Git 更新；普通安装和托管安装可升级。

停机先拒绝新业务，默认等待在途请求与下载 60 秒；超时取消升级并恢复接收，不默认强杀。安装或验证失败明确报告阶段及修复指引，不自动回滚。完成信息包含原版本、目标版本、安装验证、服务停止状态及保留配置的下一步命令，客户端应用也需重新启动。

## Windows 执行与控制

Windows console-script 启动器可能被自身进程占用，独立 Python 辅助进程持有管理锁，等待原命令退出后安装。命令先报告 `scheduled` 与日志路径，最终结果及下一步命令写入日志；scheduled 不等于安装成功。`python -m` 与 console-script 共用此流程。

控制元数据和日志按用户及 Python 环境保存。操作系统文件锁判定实例存活，不凭 PID 杀进程；loopback 上随机凭据认证的有限 JSON 通道负责控制。显式重启沿用启动配置及环境覆盖，元数据可能包含敏感配置，不应上传或提交。

## 兼容边界与验证

- 同一环境升级一个发行包会同时更新 client 与 server 命令；服务环境的 client update 共用停机流程。
- 旧前台服务没有管理通道，首次迁移前须手动停止，管理命令不接管无法确认归属的进程。
- BigQMT 策略须另行替换和启动；包安装不代表策略已更新，安装验证不依赖旧 Release ZIP 附带的策略或启动脚本。
- 托管安装入口只负责首次安装，后续使用 init/start/update；开发 setup 与独立验收包保留各自用途。
- 测试覆盖目标选择、降级、无变化、editable 拒绝、失败阶段、新进程验证、单实例锁、配置延续、排空及超时恢复。Windows 控制台脱离和包替换仍须实机验证，模拟通过不替代部署验证。
