# 完整 QMT 策略探针

对应脚本：[probe_bigqmt_strategy.py](../../scripts/probe_bigqmt_strategy.py)。
这是设计取证脚本，不是新适配器或可部署的策略桥。

**当前无需继续财务探测。** 用户已将新 adapter 财务范围收敛为五张核心表，
股东信息不再纳入实现与验收。下面保留历史复现方法；阶段 8 结果未解决缺行，
不再重跑或增加第九阶段。

脚本顶部 `PROBE_PHASE` 选择检查阶段。当前默认为 `8`；设为 `1`～`7` 可重做此前检查。

## 运行方式

1. 在目标券商的完整 QMT 中新建一个独立 Python 策略，将脚本内容完整粘贴进去。
   脚本使用 ASCII 源码，不需要安装 qmt-rpyc 或其他第三方包。
2. 使用正常策略运行方式启动，不使用回测。不要合并到现有交易策略中。
   不需要在脚本中填账号、密钥或路径。
3. 阶段 8：出现 `top10_frame_complete` 后停止。
   阶段 7：出现 `top10_raw_complete` 后停止。
   阶段 6：出现 `financial_gaps_complete` 后停止。
   阶段 5：出现 `financial_tables_complete` 后停止。
   阶段 4：出现 `financial_probe_complete` 后停止。若出现弹窗，请记录其前一条
   `capability_read_start` 的方法名和提示文字。
   阶段 3：出现 `mapping_probe_complete` 后停止。
   阶段 2：出现 `capability_probe_complete` 后停止。
   阶段 1：出现 `init_complete` 后观察约 15 秒，再停止；
   出现 `callback_sample_complete` 表示已收集五次定时回调，也可以停止。
4. 返回所有包含 `QMT_RPYC_PROBE` 的输出。若启动失败，返回报错类型和对应源码行；
   不需要提供账户信息或完整本地路径。

必须在真实策略环境中运行。用 QMT 自带 Python 解释器单独执行无法验证策略沙箱限制，
也不会执行本脚本的 `init(ContextInfo)`。

## 阶段 8：十大股东 frame 输出（已完成，方向关闭）

实机加上 `"frame"` 后，两个表仍返回相同字典和 rank=10 的一行，未取得多行输出。
这只说明该参数未在本次调用中改变结果，不推测其内部实现。用户随后明确忽略股东信息。

阶段 7 的两张 raw 默认字典都只返回同一期的一条记录，rank=10；
这不是日志取样截断（count=1、truncated=false），不能当作完整十大股东结果。
已确认该条记录的 declareDate 和 endDate，但不能未经核实把它的公告日复制到其他行。

本轮保留阶段 7 的五字段、单证券、五天窗口，只增加第六参 `"frame"`。
候选依据是参考适配器对 data_type 的透传与源码注释，并非目标部署已验证的能力。
每张表调用一次，失败不更换格式重试。若 DataFrame 返回重复日期，按行位置输出，
同时记录索引/列名是否唯一；最多展示 12 行、10 列，保留总 shape 与截断标志。
不经过以索引或列名为唯一键的字典转换，避免取证过程丢失重复行或列。
其他嵌套结构也保留类型与有界样例。阶段 7 无需原样重跑。

以及 Balance 在公告期查询时以公告毫秒为键、保留独立报告日期。
两类十大股东 Series 的十个完整字段仍不含公告日，不能拿其他财报日期补齐。

本轮仅两次 raw 查询：TOP10HOLDER 和 TOP10FLOWHOLDER 的

重点检查同一时间键下能否保留多位股东及真实公告日，不重试、不下载、不查询账号。

## 阶段 6：股东日期与剩余财务取证（已完成）

最多六次只读查询，不需要账号：

- 根据阶段 5 已返回的公告日 `20260815`，在 `20260814`～`20260816` 用
  `announce_time` 读取资产负债表双日期和总资产，检查该日期基准下的原始时间键。
- 在原报告期五天窗口查询利润表两项 EPS、现金流期末现金的同名候选；

  调用失败不会重试或跨表拼接，实际缺失的可空数值依公共契约返回 null。
- 读取 `SHAREHOLDER` 原始候选字段，检查专用户数接口未提供的公告日能否直接取得。
- 重读两类十大股东，打印 Series 的全部字段名（最多 40 个）和每字段的有界样例。
  上一阶段只显示前三字段，因此尚不能确定后七字段是否含日期、比例及排名。
  嵌套列表仍只取前三项，保留完整列表长度，不合并同日期多条股东记录。

出现 `financial_gaps_complete` 后停止。若弹窗报字段错误，保留此前
`financial_gap_start` 的 case 名和提示即可，无需反复运行。

## 阶段 5：财报日期及八类表的候选入口

保持已取得非空结果的 `000001.SZ`、`20260629`～`20260703`、`report_time`，
最多八次只读调用，每表一次，无重试和显式下载。无需手工填账号或改日期。

- 资产负债、利润、现金流、股本、每股指标五表通过 raw 入口读取，
  每表只取公共契约需要且在参考字段清单有依据的字段，包括 `m_timetag/m_anntime`。
  重点观察两个日期是否与同一报告的业务字段具有共同时间键，以及日期值的实际类型。
- 股东户数及两类十大股东改查参考项目提供的专用入口候选 `get_holder_num`、
  `get_top10_share_holder`，先检查目标方法的实际签名。缺失或无法核对调用参数时记录跳过。
  十大股东同一日期可能有多行，不按日期去重，不把各字段独立排序后拼行。
- 保留原始时间键的数值类型，以有界键值对样例输出；DataFrame 保留行数和重复索引，
  样例仍只打印前两行。结果截断标记只用于诊断显示，不能复制到业务结果转换中。
- 利润表 EPS、现金流期末现金在参考清单没有直接证据；股本流通字段存在异名。
  这些缺口会在 `financial_tables_notice` 明确列出。本轮不猜测字段替代关系。
  后续核对公共字段定义后确认：源端缺失的可空数值允许为 null，
  必需日期和报告记录身份仍必须验证，不能以其余字段正常宣称八表已完成验收。

本轮不重复行情、期权和填充财务查询。若出现弹窗，请保留此前的
`financial_table_start` 表名、`capability_read_start` 方法名及提示文字。

- 返回类型可能为 DataFrame、Series 或嵌套字典，按实际结构打印有界样例。
  空结果不能证明字段不支持；按交易日填充的记录不能直接当作财报记录。

此次无需重跑阶段 1～3 或管道探针，也无需账户配置。

## 阶段 2：能力缺口检查

- 读取候选内置函数的签名、`__doc__` 和 `__text_signature__`，说明最多保留 4000 字符。
  对没有调用依据的全局 `get_history_index_weight` 只读取说明，不猜测参数。
- 调用全局 `get_sector_list("")`，确认顶层返回结构；板块或自定义目录名称不作为原始值输出。
  此次不遍历目录树，不能把顶层数量视为全部板块数量。
- 调用 `ContextInfo.get_sector("000300.SH")`，对最多三个实际返回且格式有效的不同成分
  调用 `get_weight_in_index`。这三条公开权重样例保留原始数值供核对，不做单位换算。
- 以实际部署的单参数签名调用 `get_instrument_detail("000001.SZ")`，
  再读取 `get_instrumentdetail("510050.SH")`，检查字段缺失范围。
  不使用其他版本资料中的第二个 `iscomplete` 参数。
- 调用 `get_option_undl_data("510050.SH")`，检查标的与合约映射的返回结构。

只读调用候选参数参考 `xtquant_big_convert` 的内置调用实现和随附资料。
随附资料仅用于生成探针，入口与语义均须以目标终端结果为准。
阶段 2 不再注册定时回调或创建管道，也不触发交易、下载和账户查询。

## 阶段 1：环境检查

- Python 版本与位数；固定候选 API 在 ContextInfo 和策略全局是否存在、是否可调用。
  可提取时只输出参数名、种类和是否必填，不输出默认值。
- 与板块、指数、下载、财务相关的其他成员名称，不调用这些未知方法。
- 标准库 ctypes 能否加载 kernel32，并创建后立即关闭一个拒绝远程客户端的临时命名管道。
  不建立客户端连接、不执行网络请求，不代表已验证管道通信。
- 两次公开数据查询：`get_full_tick(["000001.SZ"])` 和
  `get_instrumentdetail("000001.SZ")`。输出字段名、类型、数量及是否有值，不输出原始值。
- 通过 `run_time` 注册每秒一次的探针回调，最多输出五次定时和两次 handlebar 观察。
  记录回调是否与 init 同线程、实际间隔；本脚本不会主动调用 handlebar。

不导入 xtquant，不尝试 socket / ZMQ，不查询账户，不下单、撤单或下载。
临时管道创建和定时回调注册只用于验证运行环境；停止探针策略后不再需要它们。

## 结果边界

`callable=true` 只证明存在入口；签名不可提取也不等于不能调用。
`read_result.status=returned` 只证明调用正常返回，要结合非空字段及后续字段语义验证，
不能把空字典、缺字段或零条数据当成能力验证通过。
`timer_registration.status=returned` 不代表回调实际执行，必须观察后续 `callback` 记录。
探针输出的异常只保留类型，以免异常文本带出本地环境信息。

原生查询不能由这个脚本强制设置超时。每次调用前先输出 `read_start`；
如果一直没有对应的 `read_result`，返回最后一条输出即可，不需要反复重启或重复查询。
阶段 2 对应标记为 `capability_read_start` / `capability_read_result`。
下一轮将根据实机结果选择通信、调度方案，并针对实际存在的接口验证能力缺口。
