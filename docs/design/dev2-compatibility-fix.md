# 0.4.0.dev2 兼容性修复

## 复现与原因

dev1 初次验收只抽查了一份期权的行情，不能代表完整期权链可用。扩大只读查询后，510050.SH 的 96 个期权中有 46 个在 `timetag` 校验失败；指定 20261028 到期日的 22 份合约中仍有 17 个失败。V1 先验证 `time`、再验证 `timetag`，这些失败表明 Unix 毫秒字段已通过检查，但冗余显示字符串不符合约定。整批行情因此失败，影响依赖整批行情的首页盈亏和期权链。

六个 ETF（510050/510300/510500/159919/159915/159922）共 708 份期权详情的实际 RPC 查询全部成功；这不代表其行情也全部可用。

另一个问题：`get_option_list('510050.SH', '20261028')` 实际返回 20260923、20261028、20261223、20270324 四个到期日。SDK 的日期参数不等于实际到期日筛选。

## 修复

- 服务端启动日志和控制台摘要显示包版本号。
- 基线服务端适配器保留合法的 `timetag`；对不合规/缺失的显示时间，使用通过 V1 范围及整数校验的 Unix 毫秒 `time`，按 UTC+8、整数毫秒运算重建字符串。保留价格、成交量、Unix 时间值及有效的原显示格式，不依赖运行主机时区。不解析未知字符串，不猜测秒/毫秒，不用当前时间补空。源 `time` 不合法时仍返回契约错误。
- V1 JSON 快照不变，摘要仍为 `433757e3b006457531cbbe7550d96618a501e039001d05cd438d65021bf6a9a6`。
- a-options 先查详情并按 `ExpireDate` 精确筛选，然后请求本到期日行情，避免无关到期日影响当前期权链。
- 复核 a-trader 的嵌套 ExtendInfo、split 行情/分红、时间单位、资产字段和交易结果未知处理；既有迁移保持。两个应用依赖版本同步到 dev2。
