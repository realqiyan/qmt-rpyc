# BigQMT 部署与实机验证

当前可选择 `QMT_RPYC_ADAPTER=bigqmt`，通过本项目维护的单文件策略访问完整 QMT。
它不导入 xtquant，也不连接参考项目的服务。外部客户端继续使用原有 RPyC 和认证配置。
0.6.0 提供 27 项业务操作（公共契约 v4），包含 STOCK 账户交易。下文保留了逐阶段
验收记录，交易恢复后的行为与发布决定见交易说明及发布前验收报告。安装和只读检查不下单。

## 生成并运行策略

在更新后的源码仓库生成策略（Linux 或 Windows 均可）：

```console
python scripts/build_bigqmt_strategy.py --output dist/bigqmt_strategy.py
```

将生成文件复制到完整 QMT 的一个独立策略，保存后运行。使用此前已验证的策略运行方式；
无需配置账户或价格。看到 `QMT_RPYC_BRIDGE ready; read_only=False; protocol=4`
表示监听已建立，业务请求能否完成由客户端检查确认。旧探针策略可以停止。
同名桥只能运行一个，默认管道为 `qmt_rpyc_bridge_v1`；需要多实例时，同步修改策略入口段
`PIPE_NAME`、客户端 `--pipe` 和服务配置。终端 Python 3.6.8 不安装本项目包；
外部服务使用 Windows 64 位 Python 3.10/3.11。

## 本机只读检查

在 QMT 所在 Windows 机器的更新后源码仓库执行：

```bat
.venv\Scripts\python.exe -m pip install -e ".[server]"
.venv\Scripts\python.exe scripts\check_bigqmt_bridge.py
```

首次仅检查单证券快照、两根日 K、证券资料、两个交易日和一个期权合约。
无账户读取、下单、撤单、财务查询和显式下载。输出操作名、数量和错误分类，
无需发送账户或完整行情。`returned` 只表示样本调用成功，不证明覆盖完整或数据新鲜。
首次结果确定后，可加 `--extended` 验证全市场快照、板块树和沪深 300 当前权重。

## 接入 RPyC

同一 Windows 用户运行 QMT 和服务，在现有服务配置中设置：

```dotenv
QMT_RPYC_ADAPTER=bigqmt
QMT_RPYC_BIGQMT_PIPE=qmt_rpyc_bridge_v1
QMT_RPYC_BIGQMT_TIMEOUT=30
QMT_RPYC_DEBUG=0
```

保留认证密钥、监听与 TLS 配置；新 adapter 不使用 QMT_PATH、QMT_XTQUANT_PATH 或账户配置。
`qmt-rpyc-server --config PATH check` 直接验证本机策略管道，不要求旧 RPC、MiniQMT 或 SDK 恢复。
服务可先于策略启动，健康状态先为未连接；心跳成功后关联新桥实例。
客户端与服务需同时更新到契约 v3：仅日 K、财务五表，不再包含股东表。

## 实现与验收边界

2026-09-28 用户在 Windows 上运行测试包的默认只读检查，五项均返回成功：
`market.get_ticks`、`market.get_daily_bars`、`instruments.get_details`、
`market.get_trading_dates`、`options.get_contract_details`。这确认了当前样本经过
真实管道、策略线程与公共模型转换；输出中的日 K count=1 是证券数，不能据此断言实际 K 线条数。
该检查没有覆盖远程 RPyC、完整板块树、全市场数据或长期压力，仍保留 production_ready=false。

测试 ZIP 的 `start-server.bat` 首次生成配置时默认监听 `127.0.0.1`。
远程客户端联调需在 Windows 本地将 `config.env` 的 `QMT_RPYC_HOST` 设置为可达网卡地址
或 `0.0.0.0` 并重启；系统环境变量优先于该文件。连接被拒绝发生在认证之前，
应先检查进程、监听地址和端口，不需要发送或更改认证密钥。

- 已接入行情、日 K、日历、合约、期权、板块、指数权重、分红、五表财务转换及四类兼容下载任务。
- 来源缺少必需字段不填默认值。例如部署样例的 `IsTrading=None` 无法构成 TradingReference，会返回逐项 MISSING_RESULT。
- 代表指数日历、分红向量与区间完整性、板块子目录路径、全市场选择器、空参数期权映射、非期权补充查询和复权参数组合仍需实机证据。
- 原生 QMT 调用只由策略回调线程执行，后台线程负责管道和队列。不能强制取消正在执行的原生调用；过期且尚未开始的请求不会执行。
- 请求 64 KiB、响应 16 MiB、最多四个连接、队列 32 项；超限明确失败，不截断为成功，不自动重发请求。
- 当前只读桥用截止时间淘汰失联客户的排队请求，不会即时探测等待结果的连接是否断开；这不等于取消原生操作。
- 重启更换实例标识；旧响应不能成为新调用的结果，心跳重新确认后才采用新实例。
- Windows 长期压力、原生 I/O 竞态、停止/重启与句柄数量仍待验收，已有 echo 探针和本地测试不足以宣称生产稳定。

停止时 `pending_handles_retained` 非零表示原生取消尚未完成，缓冲区仍被保留；
不能提前释放它们，应保留输出用于定位。

## 远程实机结果与分组读取修正

远程认证、契约及健康查询、快照和证券资料已通过。五种日 K 复权参数在
fill_data=False、count=2 的样本上均返回两根 K 线；深圳交易日历返回两个日期，
沪深 300 成分返回 300 项。板块树返回 2,711 项，但耗时 90.5 秒。
期权到期日查询超过默认 30 秒，指数权重超过此次测试的 120 秒等待；没有重发这两笔查询。

为减少逐项管道往返，期权发现、板块目录及指数权重改为最多 16 项一组的内部只读请求。
各原生调用仍只在策略线程执行，校验每组返回身份，不补造缺失结果。
私有桥协议升级为 2，公共契约保持 v3；服务 wheel 与 QMT 单文件策略必须一起更新，
不能混用上一版 protocol=1 的策略。分组版本的性能尚待新包实机验证。

原版沪深合并快照超过 16 MiB 响应限制；分别查询 SH 和 SZ 后返回 26,333 和
24,296 条、无逐项失败，耗时分别约 9.25 和 8.68 秒。新版本逐市场读取并按身份合并，
拒绝跨市场重复身份，不扩大帧长上限或过滤非股票。分红在独立连接上于 0.5 秒
返回两条记录；原来的超时发生在同一连接的慢指数查询之后，不能作为分红 API 卡死的证据。


## 缓存、心跳与调试

当前私有桥协议为 3，服务 wheel 与 QMT 单文件策略必须一起更新。公共契约保持 v3。
期权发现结果缓存 300 秒，最多 32 项；只缓存成功结果，同一查询并发刷新合并。
底层标的列表、到期日和期权链共享发现缓存，交易日和桥实例变化会使旧键失效。
不固定有效标的数量，不缓存行情和交易数据。

四个本地连接槽位中，一个专供心跳，三个供业务请求。本地容量等待超时不再被当作
策略断线；原生调用长时间占用策略线程仍可能导致真正的心跳超时，不能强制中断。

设置 QMT_RPYC_DEBUG=1 并重启服务即可开启调试，新测试包也提供
start-debug-server.bat。默认关闭，沿用现有认证。DebugClient 支持 context.*、
global.* 的方法描述，以及显式白名单内的原生只读调用，均在策略线程执行。
交易、下载和任意代码执行不开放；不自动重试。bridge.transport、bridge.cache_info
和 bridge.clear_cache 可分别查看连接槽位、缓存统计和清除缓存。
DataFrame/Series 以带类型标记的数据返回，数字键映射使用 items 键值对，保留原始身份。
这些改动已通过本地测试，仍待新版 Windows/QMT 实机验证。

生成的 bigqmt_strategy.py 使用 GBK 编码及 coding: gbk 声明，适配目标 QMT 编辑器；复制或保存时保持 GBK。仓库源模块仍使用 UTF-8。
