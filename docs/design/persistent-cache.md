# 查询驱动的业务持久缓存

本文记录已确认的表结构与读写规则；实现及验证边界见下节。已确认边界见 [ADR 0005](../adr/0005-server-persistent-data.md)。本次采用 SQLite、业务表及区间复用，数据仅保留最新值；无关注配置、定时采集或查询触发的后台采集任务。refresh 默认为 false。

评审已确认按本文范围完整交付，不将复权、补齐或财报区间复用延期为后续阶段；未知场景仍遵守本文明确的来源查询路径。保留严格时效规则，离线能力只承诺回答覆盖与时效均满足的请求，不承诺跨日断源后的复权历史分析。完整交付包含来源一致性验证，尚待验证的行为不能以实现了存储表替代验收。

## 实现与验证边界

`storage/policy.py` 管理按类别的有效期；`storage/repository.py` 管理业务字段、SQLite 事务和覆盖；`storage/service.py` 执行读取、刷新、按证券并发及内存结果组装；`storage/providers.py` 以显式装饰器组合原有 Provider。适配器工厂注入覆盖与价格派生策略，来源差异不散落在公共契约或数据库访问中。

已接入八个读取接口、业务表、状态与区间表、财报双口径隔离及保守失效、批量逐项错误、强制刷新依赖和存储故障降级。SQL 列由固定业务模型声明生成；数值使用 SQLite 数值列，日期使用 ISO 文本，证券占位日期保留判别结构。`generation` 是事务批次标识，不保留修订版本。服务默认启用持久数据，客户端不打开数据库。

覆盖证据分来源处理，不把实现了缓存路径等同于所有来源都可命中：

- 有明确起止日期的历史交易日历，经排序、唯一性和范围验证后可复用；没有证据的空日历不作为完整空区间缓存。
- 原始日 K 在来源报告的闭区间上建立覆盖：每个上报行都必须落在来源交易日历上，日历上缺行的交易日视为来源当日无行情。无行可证或出现日历外日期的响应仍为 observed。覆盖支持子区间、差集和具有足够记录的 count 后缀查询，不推定最早缓存记录就是上市日，也不把空结果当作已证实的空区间。来源无法自证缺行是停牌还是尚未下载的数据，缺行会一直沿用缓存直到显式 refresh。
- BigQMT 分红读取取得完整显式事件集合，先验证全部记录再本地裁剪，因此可保存来源视图覆盖及当天集合检查状态。这不是市场事实完整性认证。
- 两个现有适配器的财报，以及 xtquant 分红，尚无可靠的完整性证据，当前保存 observed 并回源返回。财报复用、替换、双口径与同口径失效路径由具有明确覆盖承诺的合成 Provider 验证；不能将它们描述为已经在实际券商财报上获得缓存命中。
- 五种复权的派生公式经实机样本对照，两个适配器共用同一份策略（同一份 QMT 数据，差别只在读取路径）：none、front、back、back_ratio、front_ratio 本地派生，含股改事件的请求回源。front 保留一个已量化的形状例外：停牌跨越除权日时来源对同一行随查询起点给出两个值，本地公式只能匹配其中一个（实测 600519 全历史 6015 行命中 1 行，13 个 ETF 约 3.7 万行命中 0 行）。
- 补齐按来源自身规则本地实现：补齐行沿用上一行收盘作为整根价格区间，前收、量额、结算为 0，持仓量沿用上一行，停牌标志置 1，源时间为该交易日的上海零点；复权先于补齐。窗口首个交易日没有真实行时不本地补齐，整项回源。来源的交易日历与补齐后的行集合逐日一致，因此「日历减真实行」即停牌集合，来源造出的行不入库。

上述保守来源路径是设计中约定的未知场景处理：财报区间复用、xtquant 分红完整性尚未取证，未取证场景保持来源路径。覆盖策略必须依据新的来源证据扩展，不能通过配置把普通成功响应提升为完整覆盖。实机核对通过客户端 debug 入口按需进行，仓库不保留一次性脚本。

## 配置

- `QMT_RPYC_CACHE_PATH`：SQLite 路径；留空使用服务端持久目录下的 `data.sqlite3`，Windows 默认 `%LOCALAPPDATA%\qmt-rpyc\data.sqlite3`。
- `QMT_RPYC_CACHE_SOURCE`：可选部署来源标识；切换到不同数据源但其他连接配置不变时修改。来源命名空间同时包含适配器、契约语义版本与部署路径/管道身份的摘要，不保存认证密钥或账户标识。
- `QMT_RPYC_CACHE_POLICIES`：JSON 对象，按类别配置 `"forever"`、`"day"` 或正数秒数。例如 `{"instruments":"day","daily_bars":"forever","financials":86400}`。未知类别和无效时限拒绝启动。修改配置并重启后按新规则判断已有数据，不改写更新时间。

类别为 daily_bars、trading_dates、dividend_events、financials、instruments、option_contracts、option_underlyings、option_expiry_dates、adjustment_events。实时与交易接口不受这些策略影响。`system.get_health().persistent_data` 报告持久化降级与读写失败计数；写入失败不等于来源查询失败。

SQLite 使用 WAL、短写事务和有界锁等待；未知结构版本或损坏数据库保持原文件并降级回源，不自动重建。清理没有自动启用；后续维护接口必须在同一事务中修正覆盖。

## 方案总览

| 决策 | 方案 |
|---|---|
| 存储位置与选型 | Windows 外部服务管理本机 SQLite，项目内实现轻量业务缓存层 |
| 读取 | 有效且覆盖足够则查业务表，否则在当前请求内回源并保存；支持日期区间复用 |
| K 线 | 仅保存原始日 K，事件另表保存，本地派生复权结果 |
| 时间 | 保存 updated_at，服务端按类别配置有效期，查询动态判断；过期不删除 |

| 故障 | 缓存读失败继续回源；写库失败仍返回完整且已校验的查询结果并记录降级 |

删除 reference.list_sectors、reference.get_sector_members、downloads.start_sectors。其余实时、交易、期权链和指数权重查询保留原有来源路径；未明确删除的下载接口保留。公共操作数量由 27 变为 24，同时新增 refresh 请求字段，必须配套升级客户端、服务端与相关契约，不能保持旧指纹静默变更。

## 组件

建议在服务端组合三个职责：类型化缓存 Provider（读取决策与结果装配）、按业务的存储访问（SQL、事务、查询）、原有来源 Provider（xtquant/BigQMT 转换）。实时读取、交易与未纳入存储的能力走原 Provider。新增代码可置于独立 storage 模块；公共 contracts 不依赖它。

数据库由外部 Windows 服务管理，放本机持久目录，不放 BigQMT 策略目录，不由客户端直接打开。数据先通过类型与边界校验再入库。批量请求按证券处理，保持原顺序与逐项错误，失败项不写成空成功。capability 判断须允许可读取的缓存数据在源离线时进入查询流程。

已确认保持各适配器现有启动依赖：本机 SDK 适配器仍要求 SDK 可导入，SDK 缺失或损坏时不新增仅存储启动模式；BigQMT 外部服务不因此新增本机 xtquant 依赖。离线查询保障针对服务正常启动后 QMT 或来源连接不可用，不能表述为任意来源安装故障下都能启动。

## 业务表

下列是建议结构，不是既有 SDK 完整性或唯一性的承诺。各表包含来源命名空间 source_scope 与更新时间 updated_at；命名空间区分部署数据源及适配语义，不仅区分适配器名字，避免切换来源后混用数据。表字段按公共模型保存，不保存原始 SDK 对象。

| 表 | 业务内容 | 建议标识或索引 |
|---|---|---|
| daily_bars | 原始日 K 全部公共字段 | 来源、代码、交易日 |
| instruments | 名称、交易所、上市等日期、股本、单位 | 来源、代码 |
| option_contracts | 标的、名称、认购认沽、到期日、行权价、合约单位 | 来源、合约代码 |
| option_underlyings | 当前期权标的集合的成员 | 来源、标的代码 |
| option_expiry_dates | 某标的当前可发现的到期日集合 | 来源、标的代码、到期日 |
| trading_dates | 已知交易日 | 来源、市场、交易日 |
| dividend_events | 分红除权事件及公共数值字段 | 按代码、事件日期建索引；来源事件时间辅助识别，唯一性待实机验证 |
| financial_balance | 按查询日期口径分别保存的资产负债表来源记录 | 来源、代码、date_basis 分区；分区内按对应日期索引，内部行标识保留重复记录 |
| financial_income | 利润表公共字段 | 同上 |
| financial_cashflow | 现金流表公共字段 | 同上 |
| financial_capital | 股本表公共字段 | 同上 |
| financial_pershare | 每股指标表公共字段 | 同上 |

证券资料的占位日期保留 kind/raw/value，不能强制转成普通日期。财报字段 m_timetag、m_anntime 分别映射报告日期、公告日期，数值字段保持现有 nullable 语义与单位。

财报不能直接假定“代码 + 报告日期”唯一；当前两日期组合的唯一性也未统一验证。已确认按 date_basis 分别保存报告日期与公告日期来源视图，业务行与覆盖均按口径隔离，允许同一来源事实重复存储，不跨口径直接读取或拼接。使用内部行标识保存区间返回的完整记录集，通过同口径范围替换更新，避免任意去重；稳定业务唯一键须依据实际来源验证。按报告日期取得的区间不能证明公告日期区间已完整覆盖。对于同口径下记录日期更正跨区间移动，采用下述保守覆盖失效规则，不把口径隔离当成记录身份问题的解决方案。

### 原始日 K 表

```sql
CREATE TABLE daily_bars (
    source_scope TEXT NOT NULL,
    code TEXT NOT NULL,
    trade_date TEXT NOT NULL,
    source_time TEXT,
    open REAL,
    high REAL,
    low REAL,
    close REAL,
    previous_close REAL,
    volume INTEGER NOT NULL,
    turnover REAL NOT NULL,
    open_interest INTEGER NOT NULL,
    source_suspension_flag INTEGER NOT NULL,
    settlement_price REAL NOT NULL,
    generation INTEGER NOT NULL,
    updated_at TEXT NOT NULL,
    PRIMARY KEY (source_scope, code, trade_date)
);
```

日期使用 ISO 日期，时间为 UTC aware 时间的规范表示。generation 用于检查当前数据批次一致性，不作为历史版本留存。主键自然支持代码、语义分区内的日期范围检索；从某个 end 向前取 count，可按日期倒序取数再还原升序，但前提是截止 end 的相应区间覆盖已确认。

adjustment/fill_data 是查询与结果派生参数，不属于原始数据存储维度；start/end/count 也不属于业务行主键。不同客户端的批量组合不影响行复用。已确认仅持久化 trade_date 早于上海当前日期的日 K；当天即使收盘仍回源且不入库，次日起按查询需要保存，不依靠收盘时间猜测定稿状态。来源后续更正仍可通过 refresh 获取。

结束日为上海当天的请求由服务端内部切分，调用方不新增参数也不感知切分：以缓存已证明的最后一个交易日为界，之前的区间走上述覆盖、缺口与落盘规则，之后到请求结束的区间固定回源为当天尾部，两段按原契约返回单一结果。尾部中已收盘的部分在取得来源证据（日历逐日对应）后照常落盘，当天部分既不落盘也不标记为可复用，因此缓存边界随日期推进而无需探测来源。缓存没有证明该窗口内任何交易日时，改用完整原请求回源，不凭自然日推测切点；请求结束日晚于当天、以及 refresh=true 的请求同样保持完整原请求回源，不参与切分。切分后由本地复现的请求，其未复权响应只有在证据证明"每个来源交易日一行"时才落盘：补齐响应可能含来源自行造出的行，这类响应照常返回但不入库。任一段来源失败即整项失败，不返回只有历史部分的半截结果。

## 元信息表

| 表 | 职责 |
|---|---|
| cache_coverage | 记录业务分区已确认可复用的日期区间，以及仅观测到数据、尚未确认覆盖的范围 |
| cache_state | 记录资料或集合的最近成功采集日、批次和状态；区分完整空集合与从未采集 |
| schema_meta | 存储结构版本与迁移信息 |

cache_coverage 建议包含 dataset、source_scope、entity_key、语义分区（例如财务 date_basis）、start_date、end_date、coverage_state、generation、updated_at。原始 K 线覆盖与事件覆盖分别维护，不为四种复权模式重复保存行情覆盖。coverage_state 至少区分 reusable 与 observed；这不是面向用户的真实市场数据完整性认证。

不能用 MIN/MAX(trade_date) 推导覆盖：中间可能缺行；也不能以“调用成功”或“下载 completed”无条件标记整个请求范围。覆盖判定需要按业务与来源验证，区分停牌、上市前、没有事件和来源缺数据。无证据的缺口保留为未知，不能永久缓存为不存在。

已确认完整原请求的来源响应只要符合现有契约即可用于本次返回，来源响应成功不等于缓存取得可复用覆盖。缺少覆盖证据时至多记录 observed，不能据此续期 reusable 区间或完整集合状态，也不能利用旧覆盖将新观测提升为已验证结果。覆盖证据须来自按业务和适配器验证的规则，现有 Provider 仅返回业务模型不足以天然提供此证据。证据的内部传递与失效检查属于实现前验证内容，不新增公共完整性承诺。

已确认区间与数据行须同事务更新。合并区间只在语义一致且没有未知空隙时进行；不同财务日期口径不能仅因日期相邻而合并。记录已获取某个来源视图不等于证明市场事实完整。

cache_state 与集合成员同时整组替换。例如刷新期权到期日时先校验完整结果，在一个事务中替换该标的旧集合并更新采集日；只做逐行 upsert 会留下已消失的成员。有效期按上海自然日判断，过期记录可以保留但不得作为当日结果返回。

### 更新时间、查询有效期与清理

已确认业务数据保存更新时间，查询时依据当前缓存时限筛选，不在行中固化 expires_at。建议 updated_at 表示最近一次成功回源验证并入库的时间，即使内容未变化也更新；单纯命中缓存不更新，防止高频读取让旧数据永不过期。使用 UTC 时间保存，与业务日期及 source_time 分开。

持续有效的历史数据默认不设年龄上限；按上海自然日有效的数据，以 updated_at 是否落在当前上海日期判断，不等同于滚动 24 小时。若某类数据以后改为时长 TTL，则查询使用当前时刻减 TTL 形成的时间下界。策略调整不更新记录、不搬迁数据；过期行留在库中，若策略允许更长时限可重新符合条件。

已确认缓存时限由服务端按数据类别统一配置，客户端不传每次请求的数据年龄要求，仅通过 refresh=true 强制刷新。策略应区分已知历史事件记录和复权所需最新事件集合：同一事件表的数据可持续保留，但其用于复权的完整集合检查默认当日有效。配置入口及名称属于实现细节，不增加新的公共业务操作。

| 数据/用途 | 已确认默认规则 |
|---|---|
| 原始历史日 K、历史财报、历史分红事件、已确认历史日历 | 无年龄上限，允许显式刷新获取更正；仍受覆盖失效规则约束 |
| 证券资料、期权条款、期权标的集合、到期日集合 | 上海自然日有效，跨日更新失败则不可用 |
| 用于复权的最新完整事件集合检查 | 上海自然日有效，失败不使用过期集合计算 |
| 当日日 K | 含当天的请求按缓存已证明的最后一个交易日内部切分，未证明部分回源，其中当天不落盘，次日起按查询需要保存 |
| 实时行情与当前账户状态 | 不持久缓存 |

行、区间覆盖、集合状态的更新时间必须一致对应实际成功刷新的范围；刷新子区间不能顺便续期其他区间，邻接覆盖的合并不能掩盖各部分时间差异。查询同时满足业务范围覆盖与时间条件；集合的有效性以完整刷新状态为准，不能过滤掉过期成员后将剩余项冒充完整集合。

后续清理可以按 updated_at 指定截止时间，与 TTL 独立；删除业务行时须同事务缩减覆盖或使相关集合状态失效，避免清理后仍声称覆盖完整。没有确认定时清理或 LRU 淘汰，不因过期自动物理删除。

### 存储故障

已确认 SQLite 读取失败或损坏时继续回源，记录错误并报告缓存降级，不自动删除或重建原文件；来源也不可用则明确报错。写入失败时仍返回完整且已校验的查询结果，不更新覆盖、更新时间或有效性，不承诺本次结果落盘。部分命中时保留已读的一致快照，在内存与可安全拼接的缺口响应组装，不仅返回缺口，也不依赖写库后重读来取得完整结果。无法取得或保持安全拼接所需的视图时，完整原请求回源。复权等依赖查询仍须取得满足规则的数据，不能以数据库故障为由使用过期事件。

## 普通查询

1. 校验请求，按证券与业务语义划分查询；解析有限日期边界。开放起点与 count 查询不得凭最早缓存记录假定已到历史起点。
2. 查询有效性与覆盖元信息；覆盖足够时按业务表过滤、排序并装配现有公共模型。
3. 范围部分覆盖时保留已读的一致快照并计算差集。对可以独立拼接的业务区间，仅同步回源读取缺口；需要上下文的补齐或复权数据扩大回源范围，不盲目截断来源请求。缺口响应不足以证明安全拼接时，改为完整原请求回源，以其响应作为本次结果，不与旧缓存盲目合并。
4. 在事务外执行 SDK 调用与结果验证；完整原请求的响应符合现有契约时允许本次返回，不把缺少缓存覆盖证据本身当作查询失败。只持久化允许入库的历史记录，在短事务中更新相应行与已取得证据的覆盖；无证据的数据不能提升为 reusable。校验失败不更新有效性。
5. 从保留的缓存视图及本次可安全拼接的内存响应组装结果，或使用完整原请求的已校验来源响应；成功返回不依赖写库成功。完整回源也失败时明确返回错误，不把局部结果当完整成功。该降级不豁免复权事件时效及强制刷新依赖规则。

含上海当天边界的查询在读取覆盖后追加一次切分，仍按上述顺序执行：缓存已证明的最后一个交易日之前的区间照常读取、回源缺口并落盘，之后到请求结束的区间固定回源为当天尾部，只在内存参与装配与派生。尾部中已收盘的部分按第 4 步取得证据后落盘，当天部分不写业务行、不产生 reusable 覆盖、不写入覆盖元信息；历史段与当天段按原契约返回单一结果，调用方不需要传参或调整解析。任一段来源失败则整项失败，不返回只有历史段的结果；缓存没有证明窗口内任何交易日时改用完整原请求回源。

交易日历使用同一切分；开放起点或 count 的日历请求不切分，仍按原路径回源。切分只减少重复回源，不扩大可回答的范围：含当天的查询在来源不可用时仍然失败。复权或补齐的含当天日 K 请求是否切分由"本地能否复现该请求自己的结果"决定，而不是由请求标志决定：复权由派生策略判定（未取得验证的模式整段回源，一次调用），补齐由本地补齐规则判定（窗口首个交易日无真实行时不补齐，整项回源）。已验证的复权可由本地事件集合派生，停牌缺口由本地补齐复现。

日 K 请求的起点同样由服务端解析：未设置 start 时取结束日期前一年（结束日期缺省为上海当天），起点早于来源报告的上市日期时以该日期为准；解析后的窗口即回源、覆盖与落盘范围，因此缓存不会把上市前的补齐行当作历史。上市日期缺失、为占位值或来源不可用时保持调用方传入的起点，不推测起点。该解析是行为变更，manifest 的 behavior_revision 由 1 升到 2，客户端与服务端须同步升级；直接使用 RPC 的调用方不再能取得"起点不限制"的日 K 结果。

例：已确认覆盖 1—6 月，查询 3—4 月直接读取 daily_bars；查询 5—8 月在语义允许时回源补 7—8 月。若仅存了一些 1—6 月的行，没有确认覆盖，则不能使用该范围声明命中。

同一业务分区内合并并发缺口查询，等待者获得锁后重新检查覆盖；不同代码保持有界并发。SDK 调用不持有 SQLite 写事务，不引入进程级 SDK 串行锁。

## 显式刷新

八个纳入缓存的读取接口接受 refresh=False；true 时本次请求跳过桥接缓存，仍遵守批量上限与原返回类型。资料及集合成功后替换当前值；历史区间在覆盖得到确认后原子替换相应范围，删除来源已撤销的旧记录，避免仅 upsert 导致旧记录残留。

查询范围不足以确认替换完整性时，不删除未知区域或把部分响应提升为完整覆盖。刷新失败向调用方报错，保留旧数据；日级旧数据仍服从过期规则。refresh 不是 SDK 下载指令，不创建后台任务。

财报按一种日期口径成功更新后，在同一事务中使同来源、同证券、同财务表的另一口径视图覆盖整体失效；旧行可保留，但不得作为有效结果返回，也不能通过放宽 TTL 恢复其覆盖。另一口径后续查询须回源并在取得覆盖证据后替换相应范围，不能合并旧视图记录来冒充完整结果。首次回源补缺也遵守此规则。

已确认同口径保守失效：无法凭稳定记录身份确定更正影响时，同一事务还须使当前日期口径的其他区间覆盖失效，仅保留本次取得证据的范围可复用；若本次无覆盖证据，则不留下可复用范围。历史行可保留用于后续替换或清理，但失效行不能参与有效结果。只有实际来源证据证明能够精确定位更正影响时，才可缩小失效范围。

这意味着财报不能仅因为旧区间此前有效，就将它与新取得的缺口拼接：无法排除日期跨区间更正时，应完整回源本次请求范围，按已确认的完整请求降级规则返回和保存，而非强制获取该证券全部历史。其他证券或其他财务表的覆盖不因此失效；来源失败或存储事务回滚不提交本次覆盖变化。历史财报无年龄上限不代表覆盖永久有效。

已确认复权日 K 查询的 refresh=true 强制刷新本次计算所需的原始日 K（含必要的补齐上下文）和该证券完整事件集合，当天已有事件检查结果也不复用。以证券为单位，先在内存取得并校验全部必要来源依赖，再计算结果；任一依赖失败，该证券返回失败并保留旧存储，不提交本次部分依赖更新。全部依赖成功后，允许持久化的日 K、事件集合及相应状态在一个短事务中更新；写入失败则回滚并返回本次已校验的内存结果，不承诺落盘。批量请求保持逐项成功或失败，不扩大为整批原子更新。

## 复权与补齐边界

原有两适配器把 adjustment/fill_data 交给来源；新增持久层按来源策略决定能否本地派生。SQL 主键不能证明不同查询边界的来源数据可以拼接，仍须依据覆盖与派生证据。

### 原始价格与事件分离（已确认）

实际 BigQMT 的 ETF 现金分红及股票送转样本支持这一方向：原始价格与全量事件可以重现所采样的四种复权结果，改变样本查询起止边界不改变重叠记录。此结论针对已采样行为，不证明 SDK 的物理存储布局，也不替代配股、特殊股改和停牌补齐验证。

已确认 daily_bars 保存未复权、未人工补齐的真实日 K，主键为 (source_scope, code, trade_date)，不含 adjustment/fill_data 维度。dividend_events 保存来源完整事件字段，按日期裁剪原始 K 线后，在服务端派生所需的复权结果，不持久保存多份派生价格。外部 adjustment 参数继续保留。

原始 previous_close 必须按来源保留；除权日的参考昨收不一定等于上一交易日原始 close，不能用相邻行重建。事件时间与交易日按上海日期对齐，不直接截取 UTC 日期。

对已采样数据，OHLC 与 previous_close 使用相同的按行日期变换，其余字段没有观察到变化。现金与送转的普通复权可用事件的仿射变换组合表达，等比复权通过事件 dr 的累计乘积表达；dr 本身仍是单次事件比率。通用算法必须继续验证特殊事件，不能将这一采样结论推广为任意证券的已验证实现。

事件依赖范围不是 K 线查询范围：前复权可能依赖查询结束日之后的事件，后复权可能依赖查询开始日之前的事件。需要管理证券全量事件及其已检查的最新日期。已确认所有复权查询要求事件集合在上海当天成功检查过；当天首次查询同步回源更新，之后复用，无后台刷新。跨日更新失败时复权查询报不可用，已覆盖的未复权历史查询仍可离线读取。事件更新只更新事件表与计算依赖，不重写原始 K 线；已知历史事件持续保留不等于当天集合已确认最新。

补齐语义已按实机取证落地：复权先于补齐、补齐行沿用上一行收盘；跨标的、跨模式的历史对照逐字段一致。front 的例外形状与其影响面见「覆盖证据分来源处理」一节。来源无法区分停牌与尚未下载的缺行，缺行只按"来源当时未提供"处理。count 与补齐的组合经同一批对照：读数逐字段一致，请求数量超过可用行数时来源不补齐到 count、仍从首根 K 线返回。

同日复核了复权拼接：5 种复权模式下，本地由事件集合派生与来源自身读数在闭合日期上逐字段一致（区间延伸到当天、含 1 个分红事件），因此已验证复权的含当天请求参与切分；该结论限于已采样的来源，xtquant 未取得同类样本，仍按完整原请求回源。

### 实机取证方法

实机验证从外部 Python 环境通过 DebugClient 读取实际 BigQMT，不依赖公共业务契约协商，不改变部署配置。需要策略桥已连接且调试入口已启用。采样指定已知除权事件的 code/start/event/end，满足 start < event < end < 上海今日，整个区间不超过 90 个自然日。本次调查用的临时探针及其测试已移除，本文保留可复用的验证方法。

验证时读取原生方法描述与原始分红资料，按五种 adjustment、两种 fill_data，以及完整区间/事件前区间/事件起区间共 30 组读取 K 线，最后再次读取分红资料检查期间是否变化。subscribe=False，不调用下载或交易，不重试失败调用。采样输出应保存在仓库外；采样完成不表示公式或覆盖已经验证。

收到数据后按以下顺序分析：

1. 确认事件确实存在，事件前后均有有效原始 K 线；缺失样本不能证明复权正确。
2. 对齐日期与字段，比较完整区间和子区间的公共记录，判断 start/end 是否改变复权基准或补齐结果。
3. 逐字段比较 none 与四种复权结果，区分乘法与加法/仿射关系；不能仅从收盘价推断昨收、成交量、金额、结算价也采用同一变换。
4. 将观察到的变换与原始事件字段对照。现金分红、送转、配股及多事件累计分别验证；一个现金分红样本不能证明全部算法。
5. 以 SDK 返回值为对照验证本地计算。未知锚点、精度与特殊事件不能通过放宽比较阈值掩盖。

未复权且不补齐的日 K 可优先验证逐日复用；fill_data=true 的边界可能需要前一有效记录，回源必须考虑上下文。分红更正后后续复权查询使用新事件集，不改写原始日 K；同次查询必须使用一致的事件视图。

## 实现前与验收时的验证项

- 停牌补齐与特殊事件继续验证。
- 来源覆盖证据、合法空结果、财报与分红事件身份，以及开放范围/count 的边界语义。
- 财报两种日期口径记录隔离、另一口径整体失效、同口径其他区间失效；以公告日期从 4 月更正到 5 月为例，验证旧 4 月记录不参与新有效结果，缺口不能安全拼接时完整回源本次请求范围。
- 当天事件已检查后再次强制刷新复权日 K，须重新读取事件；任一必要依赖失败不得提交部分更新，落盘失败仍可返回完整内存结果。
- 服务端策略配置校验与策略变更后旧数据重新判定；未来按更新时间清理时的覆盖一致性。
- SQLite 运行配置、并发刷新顺序控制、迁移和回滚细节。
- 完整原请求回源成功但无覆盖证据时可返回且不产生 reusable；缺口不能安全拼接时完整回源；部分命中且写库失败仍返回完整结果。
- 含当天边界的切分：历史段须逐字段等于同区间单独读取的结果；盘中当天那根会变化，不能用同一次查询内的两次读取差异判定切分错误，切分等价性按"一次取完整闭区间"与"任意中点切成两段分别取"的实机对照确认。落库检查须确认任何不早于上海当天的日 K 行与日历项都没有入库，并确认尾部已收盘部分在取得证据后确实推进了覆盖边界。
- 来源连接不可用时已有合格数据可读；需要本机 SDK 的适配器在 SDK 导入失败时仍按现有要求拒绝启动。

现有两适配器明确拒绝无法证明的未来交易日查询；缓存层不会因增加一张日历表而扩大来源能力。日历的当天切分同样只重排读取路径，不新增可回答的范围。
