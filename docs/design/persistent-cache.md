# 查询驱动的业务持久缓存

服务端保存最近成功取得的业务数据，在查询范围、覆盖与时效均满足时减少回源并支持离线读取。本文集中记录缓存选择理由、当前实现及来源验证边界；调用参数见 [API 文档](../api/contract.md#持久数据读取)。

## 选择与范围

使用 Windows 外部服务管理的本机 SQLite，以业务表和覆盖区间保存数据，避免部署独立数据服务及按整次请求参数重复缓存。只保留最新值，不保存历史修订或确定版本的回测数据集；不做关注配置、定时采集、后台刷新、LRU 或自动清理。缺失与过期的数据在当前查询内同步取得，下载任务完成不能证明覆盖。

持久层以类型化 Provider 装饰器组合来源，公共 contracts 和客户端不依赖数据库。原始日 K 与事件分开保存，查询时派生价格，避免事件更新后重写多份复权行情。代价是需要单独验证覆盖、事件时效和本地派生与来源的一致性。

纳入八项读取：日 K、交易日历、分红事件、财报、证券资料、期权条款、期权标的列表、到期日集合。实时行情、账户与交易、期权链和指数权重读取保持来源路径。离线保障针对服务正常启动后来源连接不可用；xtquant 缺失或损坏时仍拒绝启动，不增加仅数据库启动模式，BigQMT 不增加外部 SDK 依赖。

## 组件与配置

| 模块 | 职责 |
|---|---|
| `storage/policy.py` | 按类别判断时效及来源命名空间 |
| `storage/repository.py` | 业务表、SQLite 事务、覆盖与状态 |
| `storage/service.py` | 查询决策、逐证券并发、依赖采集和内存组装 |
| `storage/providers.py` | 显式装饰类型化 Providers |
| `adapters/storage_evidence.py` | 按实际来源判断可复用覆盖 |
| `storage/adjustment.py` | 复权与补齐公式 |

适配器工厂注入来源策略，差异不扩散到公共契约或 SQL。数据库在外部服务持久目录，客户端及 QMT 策略不直接打开。

- `QMT_RPYC_CACHE_PATH`：留空使用服务持久目录下的 `data.sqlite3`，Windows 默认为 `%LOCALAPPDATA%\qmt-rpyc\data.sqlite3`。
- `QMT_RPYC_CACHE_SOURCE`：可选来源标识。命名空间还包含适配器、契约语义版本和部署路径／管道身份摘要，不包含认证密钥或账户标识。切换数据源须避免混用旧覆盖。本次收紧规则由部署方清空旧缓存，不增加命名空间迁移或隔离机制。
- `QMT_RPYC_CACHE_POLICIES`：类别到 `"forever"`、`"day"` 或正数秒数的 JSON 对象，例如 `{"daily_bars":"forever","financials":86400}`。无效时限与未知类别拒绝启动。

策略类别的权威定义是 `storage/policy.py`。修改策略并重启后动态判断已有记录，不改写更新时间；延长 TTL 可使未失效记录重新满足时效，但不能恢复已经撤销的覆盖。

## 表与元信息

业务表字段由 `storage/repository.py` 的 `DATASETS` 及公共模型生成，不另维护一份 SQL 定义。

| 表 | 内容与查询分区 |
|---|---|
| `daily_bars` | 来源、证券、交易日下的真实未复权日 K |
| `dividend_events` | 来源事件字段，按证券与事件日期查询 |
| `trading_dates` | 来源市场的交易日 |
| `instruments`、`option_contracts` | 当前证券资料及期权条款 |
| `option_underlyings`、`option_expiry_dates` | 当前完整集合 |
| `financial_balance`、`financial_income`、`financial_cashflow`、`financial_capital`、`financial_pershare` | 按证券、财务表及 `date_basis` 隔离的来源视图 |
| `cache_coverage` | `reusable` 与仅观测范围、更新时间及事务批次 |
| `cache_state` | 完整集合或复权事件检查状态 |
| `schema_meta` | 数据库结构版本 |

业务表共用 `(source_scope, entity, basis, day, position)` 存储键；`position` 保留同日重复记录，不猜测财报唯一身份。`day` 和覆盖边界用日期序数，业务日期字段为 ISO 文本，aware 时间按 UTC 保存。数值保留 SQLite 数值类型，占位日期保留判别结构。`generation` 为事务批次标识，不是修订历史。

`adjustment`、`fill_data`、`event_cutoff` 和请求组合不产生多份行情存储。原始 `previous_close` 按来源保留，除权日参考昨收不能由相邻原始收盘重建。

## 覆盖与时效

成功响应可用于本次返回，不等于后续查询可复用。行和覆盖必须同事务更新；不能凭 MIN/MAX 日期、调用成功或下载完成推定中间没有缺口。仅在相同业务语义下合并覆盖，合并不能掩盖不同范围的更新时间。

| 来源数据 | 当前覆盖证据 |
|---|---|
| 交易日历 | 显式闭区间，非空、排序、唯一且日期在范围内 |
| 原始日 K | 闭区间中每个来源交易日恰有一根真实行情，日期与日历逐日一致 |
| BigQMT 分红事件 | 来源先读取并验证完整显式事件集合，再本地裁剪，可保存来源视图覆盖 |
| xtquant 分红、两个适配器的财报 | 尚无可靠完整性证据，保存观测但继续回源 |

缺少完整性证据的空响应或缺口保持未知；行情缺行可能是停牌或尚未下载，不能证明永久不存在。经来源验证的完整空集合（例如 BigQMT 的空事件集合、空标的或到期日集合）可按覆盖、状态与时效复用，须区别于从未采集。来源视图覆盖不等于市场事实完整性认证。财报的覆盖、替换及失效机制由具有明确承诺的合成 Provider 验证，不描述为实际券商财报已经缓存命中。

| 数据／用途 | 默认时效 |
|---|---|
| 已证历史行情、日历、分红、财报 | 无年龄上限，仍受覆盖失效约束 |
| 证券资料、期权条款、标的与到期日集合 | 上海自然日有效 |
| 复权所需完整事件集合检查 | 上海自然日有效，过期后同步更新 |
| 当天行情与日历 | 本次读取可返回，当天行与覆盖元信息均不落盘 |

`updated_at` 记录成功采集的时间；缓存命中不续期。日级时效按上海日期，TTL 按当前查询时间判断，过期不删除。集合整组替换并更新状态，不能滤掉过期成员后把剩余项冒充完整集合。已知历史事件可持续保留，不代表完整集合已在当天检查过；跨日检查失败则复权查询不可用，已证未复权历史仍可离线读取。

单证券查询取得证券锁后固定采集开始时间与上海日期。读取、依赖和落盘使用同一上下文，跨午夜完成不把开始时仍为当天的数据提升为历史。不同证券有界并发，同一分区等待者取得锁后重新检查覆盖；来源调用不持有 SQLite 写事务，不增加全局 SDK 串行锁。

## 查询与刷新

1. 校验并按证券、业务语义划分请求；解析日期边界。
2. 读取有效行、覆盖和必要状态。覆盖足够则在内存装配结果。
3. 可安全拼接时仅回源缺口；缺口证据不足或依赖窗口不安全时，完整原请求回源，不返回半截结果。
4. 来源响应校验成功后，允许入库的行和元信息在短事务中提交。没有证据的响应只保存观测，不能续期旧覆盖。
5. 返回一致的内存结果，不依赖写库后重读；来源也失败时明确报错。

非 count 日 K 的缺省起点为结束日期前一年；早于已知上市日则裁剪至上市日，上市日期未知时不推测。count 不套用一年起点，也不凭最早缓存行假定已到历史起点。公共窗口与 cutoff 语义见 [API 文档](../api/contract.md#持久数据读取)。

结束日为上海当天时，以缓存已证明的历史边界切分，后续未证明尾部回源；尾部已收盘部分在取得证据后推进覆盖，当天不保存。没有可用切点、未来结束日或 `refresh=True` 时保持完整来源路径。复权和补齐仅在可安全本地派生时切分；任一段失败则整项失败。交易日历的开放起点及 count 查询不推定历史起点。当前两个适配器拒绝无法证明的未来日历，缓存不扩大来源能力。

`refresh=True` 跳过桥接缓存，不隐式下载。资料和完整集合替换当前值；已证历史范围原子替换并删除来源撤销的旧记录，部分观测不删除未知区域。复权刷新同时强制读取原始行情和完整事件集合，必要依赖全部成功后才提交；任一失败保留旧依赖。原子性以单证券为单位，不扩大为整批。

### 财报视图与失效

财报按报告日期和公告日期保存独立视图，允许重复业务事实，不跨口径复用或合并。未证实稳定记录身份时，更新一个口径会同事务撤销该证券、该表的另一口径覆盖，以及同口径的其他范围覆盖；仅本次取得证据的范围可复用，无证据则不保留可复用范围。旧行可留存，但不能参与有效结果，放宽 TTL 也不能恢复覆盖。

这个选择接受更多回源和存储，以防日期更正跨区间移动后新旧记录并存。缺口不能凭旧覆盖安全拼接时，完整回源本次请求范围，不强制查询全部历史，也不影响其他证券或财务表。未来只有来源证据支持稳定身份及精确更正影响时才能缩小失效范围。

## 复权与补齐

本地公式处理 `none`、`front`、`back`、`front_ratio`、`back_ratio`。先按 `event_cutoff` 裁剪，再筛选相关事件：front 系列取窗口起点之后的事件，包括结束日之后；back 系列取窗口终点及之前的事件。相关事件含非零股改标记时不本地派生。没有 cutoff 时要求可复用且有效的事件集合；显式 cutoff 可使用本次读取的事件，即使来源不证明事件覆盖，但仍不能跳过公式与窗口检查。

历史闭区间 count 先选截至 end 的连续有效缓存后缀，再以首根行情判断前复权事件相关性。窗口外的老股改不会阻断复用；依赖满足覆盖和时效时可离线回答。缓存后缀不足则按来源路径处理。含当天且有未证明尾部的 count 保留切分前的保守判断，可能因历史股改整段回源，不扩张此次闭区间修复的保证。

### front 的窗口例外

实际 BigQMT 在跨除权日的缺行窗口中，可能随查询起点改变同一行的 front 值。2026-10-03 的对照中，74 组非空且公式可处理的未补齐比较只有茅台 2006-04-24—2006-06-13 出现差异：2006-05-25 的 OHLC 与前收受影响，相关事件的股改标记均为 0。将起点改为 2006-05-19，收盘由 -289.368079737 变为 -288.924052690，差约 0.444027 元；开启补齐也复现。近期现金分红、2015 年送转与所采 ETF 样本匹配本地公式，这是样本证据，不是任意证券的等价性认证。

因此 front 有相关事件时，派生前要求真实行情逐日对应整个窗口的来源交易日历，不能用补齐行证明完整性。缺行或日历证据不可用时完整原请求回源；无相关事件时不加此检查，这项额外条件不扩展到 front_ratio。设置 cutoff 而无法安全派生时明确失败，不用锚定最新的来源响应替代，也不提交部分原始行情与事件更新。

### 公式及补齐顺序

现金与送转按事件组合仿射价格变换，等比复权使用单次事件 `dr` 的累计乘积。已采样行为中 OHLC 与 previous_close 同样变换，其余字段不变；特殊事件继续依实际部署验证，不能只从收盘价推断其他字段。

先复权，再按日历补齐，最后按 count 裁剪。补齐行整根价格沿用上一行收盘，前收、量额和结算为 0，持仓量沿用上一行，停牌标志为 1，源时间为该交易日上海零点。窗口首个交易日无真实行时不本地补齐，整项回源。来源或桥接造出的补齐行不入库；补齐可回答本次查询，但缺行仍不能建立可复用覆盖。可用记录不足时不补到请求 count。

## 存储故障与验证

SQLite 使用 WAL、短事务及有界等待。读取失败、损坏或未知结构版本时保留原文件并降级回源，不自动重建。写入失败回滚且不更新覆盖、状态或时效，但仍返回已校验的完整内存结果。降级不能使用过期事件或绕过强制刷新。`system.get_health().persistent_data` 报告降级和读写失败计数。

没有自动清理；未来清理须在同事务修正覆盖及集合状态，防止删除行后仍宣称完整。

合成 Provider 和真实 SQLite 测试覆盖并发隔离、双日期口径、缺口降级、刷新回滚、跨午夜、存储故障及闭区间 count 离线复用。实际来源验证经 [DebugClient](../api/debug.md) 只读取证，不依赖业务协商，不调用下载或交易，采样输出保存在仓库外：

1. 读取实际方法描述与全量事件，选择事件前后均有真实行情的历史窗口。
2. 比较五种模式、两种 fill_data 下完整窗口与子窗口的公共记录；前后再次读取事件检查是否变化。
3. 逐字段对齐日期、原始数据及来源结果，分别验证现金、送转、配股和多事件组合，未知锚点或差异不能靠放宽阈值掩盖。
4. 对含当天的切分，比较闭合历史段；当天会变化，不能用重复盘中读数差异判断切分失败。

来源覆盖及特殊事件尚未验证的场景保持原请求回源。测试通过不表示券商财报完整性或所有停牌窗口已经得到实机认证。
