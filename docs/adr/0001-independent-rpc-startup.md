# RPC 独立启动，QMT 在后台连接

券商维护期间，首次 QMT 连接失败会阻止 qmt-rpyc 的 RPC 服务启动。用户于 2026-09-12 确认采用方案 B：RPC 独立启动，QMT 的首次连接及后续重连在后台进行，使服务启动不以交易连接成功为前提。

比较过的方案包括首次同步尝试失败后降级启动，以及将 SDK 隔离到子进程。前者仍可能因首次连接阻塞而无法启动 RPC；后者能提供更强的原生故障隔离，但会显著增加接口转发、回调及资源管理成本。本次选择进程内后台连接，不承诺自动恢复 SDK 原生调用永久阻塞或进程崩溃。

行为设计已确认，具体约定和实现进度见[设计记录](../design/background-qmt-connection.md)；目前仅部分实现完成。SDK 导入在实际券商部署中的副作用也需验证，不能由仓库中的 API 发现代码推断其绝不会阻塞。
