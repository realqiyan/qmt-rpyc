# 在本项目维护完整 QMT 策略桥

新增完整 QMT 适配器及配套策略，由独立的 qmt-rpyc 服务通过适配器调用 QMT 内置策略，继续提供现有类型化公共契约。参考 `xtquant_big_convert` 的调用映射与运行约束，但不将其整套客户端、兼容层和策略桥作为运行依赖，以便本项目统一维护部署、来源转换及结果语义，避免引入其顶层 xtquant 包冲突与额外兼容行为。

新适配器仅依靠完整 QMT 的内置策略能力，必须独立于原生 xtquant / XtQuantServer，不以原生 SDK 补充缺失能力。这样只有完整 QMT 策略环境的部署也能使用新适配器；代价是参考实现中的原生 SDK 回退不能复用，能力缺口需要继续调查、实机验证和补齐。

内部通信采用 Windows 同机命名管道，远程访问继续由现有 RPyC 提供，避免额外部署中间件和依赖策略环境的网络模块。用户委托本项目作此技术选择并要求稳定可靠；必须验证异步读写、取消清理、断线恢复和未知结果不重发，不能凭管道创建成功就宣称可用。详见[可靠性要求](../design/bigqmt-reliability.md)。

本项目需要维护策略部署和内部通信，并在目标券商 QMT 中验证能力。其余实施细节仍在[设计讨论](../design/bigqmt-adapter.md)中确定。
