# 服务端按需持久数据层

为减少对原始数据源的依赖并提高重复查询性能，用户已选择服务端持久数据层：已保存且满足查询范围与时效要求的数据，在原始源不可用时仍可读取。相比仅用于加速的透明缓存，此方向需要管理覆盖范围和数据更新；当前不选择独立数据服务。

首期范围已确认为已结束交易日的历史行情、历史事件与报告，以及证券资料、期权条款、交易日历等较慢变化的资料。另纳入 instruments.list_option_underlyings 与 options.get_expiry_dates，按上海自然日判断有效性，跨日必须刷新，刷新失败报不可用，不返回过期值。按天存储不表示保留每天的历史版本；BigQMT 已有标的缓存的过期返回旧值行为也须统一到此规则。实时数据不存储；期权链、指数权重与当前账户状态不在首期存储范围内。

本次方案删除 reference.list_sectors、reference.get_sector_members、downloads.start_sectors 三个公共操作；这是公共契约变更，需要同步处理版本、客户端入口、实现、测试与文档，不能维持旧契约身份静默删除。

数据仅保留最新值，不保留修订版本。用户随后取消关注标的配置及自动采集：不做定时采集、关联期权合约自动采集，也不在查询遇到大缺口时创建后台采集任务。此前主动采集的默认起始日期与按标的覆盖配置随之撤出方案。

已确认的默认有效性规则：已结束交易日的日 K、历史分红、历史财报及已确认的历史日历范围持续可读，后续取得更正时覆盖旧值，更新失败不使已有历史整体失效；证券资料、期权条款与上述两项期权发现数据按上海自然日有效。未来日历若来源支持则按天刷新，当前适配器仍拒绝无法确认的未来范围，不因缓存增加而扩大能力。历史结果表示最近成功取得的修订结果，不保证已取得源端最新更正。

取消自动采集后，原混合补齐方案由查询驱动存储替代：有效数据直接读库，缺失或过期时在当前请求内查询原始源，成功后保存并返回；不启动后台采集，也不持续跟踪该标的。来源不可用时仅提供满足范围和有效期要求的已有数据。有效期规则本身不意味着存在后台刷新。现有下载接口不因取消新增采集功能而额外删除，下载任务 completed 仍不能作为入仓完整性的依据。

已确认区分本次来源查询成功与后续缓存可复用：完整原请求回源成功且符合现有契约时允许返回，即使尚无区间覆盖证据；缺少证据不得标记 reusable。仅查询缺口后无法证明安全拼接时，改为完整原请求回源，不把局部响应当成完整结果，也不因新增缓存而拒绝原本符合契约的来源结果。此规则不豁免已确认的复权事件时效及强制刷新依赖要求。

已确认保持现有适配器启动前提。离线能力覆盖服务正常启动后 QMT 或来源连接不可用的情形；需要本机 SDK 的适配器仍要求 SDK 安装完整且可导入，不新增 SDK 损坏或缺失时的仅存储启动模式。BigQMT 外部服务保持其现有启动依赖，不额外要求本机安装 xtquant。

存储选型已确认为 SQLite 加项目内轻量业务缓存层，不部署独立数据库服务。SQLite 负责持久化、索引和事务，项目代码负责按接口的有效性、复用范围与回源规则。相较直接使用通用键值缓存，这允许表达日期范围与业务查询语义；不扩展为通用缓存框架。缓存层拟组合现有类型化 Providers，在 Windows 外部服务管理本机数据库，xtquant/BigQMT 适配器继续负责来源转换。

历史数据采用业务表逐条存储并支持区间复用，不采用以整次请求参数为键的结果缓存。八个纳入持久化的读取接口支持可选 refresh 参数，默认为 false；true 时跳过桥接缓存，重新查询来源，成功后更新，失败报错且保留原数据，不隐式执行 SDK 下载或创建后台任务。具体设计见 [持久缓存设计草案](../design/persistent-cache.md)，其中未确认细节仍是建议。

财报已选择按报告日期与公告日期分别保存来源查询视图。两个日期口径分别管理业务记录及覆盖，允许重复存储，不跨口径直接复用记录；不以尚未验证的记录身份强行合并为共享明细。成功更新一个口径时，使同来源、同证券、同财务表的另一口径视图失效，防止旧视图继续命中。此选择以额外存储及回源成本换取记录身份未明确时的保守查询语义，不要求小范围查询触发全量财报刷新。

已确认同一日期口径也采用保守失效：无法凭稳定记录身份确定更正影响时，成功更新后使同来源、同证券、同财务表、同日期口径的其他区间覆盖失效，仅保留本次取得证据的范围可复用。旧行可保留但不能参与有效结果。此规则接受更多回源，以避免日期更正跨区间移动后新旧记录并存；未来只有实际来源证据支持精确定位更正影响时，才可缩小失效范围。不因这一规则强制查询证券全部财报历史。

来源查询成功且结果校验通过、但 SQLite 写入失败时，已确认本次仍返回完整查询结果并记录持久化失败，不更新覆盖与有效期，不承诺本次结果已经保存。部分命中时保留已读的一致缓存快照，与本次已校验且可安全拼接的缺口结果在内存组装；不能仅返回缺口，也不依赖写库后重读。无法安全拼接时按完整原请求回源规则处理。

SQLite 无法读取或损坏时继续回源，记录故障并报告缓存降级，不自动删除或重建原数据库；来源也不可用时明确失败。业务数据保存更新时间，查询时按当前缓存时限规则判断是否可用。过期不删除，调整有效期不改写历史数据；后续清理可按更新时间筛选，与查询有效期分离，不引入后台采集。

缓存时限由服务端按数据类别统一配置，不增加每次查询指定最大数据年龄的参数；客户端只通过 refresh=true 强制刷新。配置改变后按新规则判断现有记录，无须重写数据。

已确认日 K 仅持久保存原始价格，分红除权事件另表保存，查询时在本地计算所需复权结果，不保存多份复权价格。daily_bars 主键为来源、证券代码、交易日，adjustment 保留为查询参数。此选择避免事件更新后重写历史派生价格，但要求验证本地计算与部署 SDK 的一致性，并单独管理事件依赖的覆盖和新鲜度；停牌补齐及特殊事件边界仍待验证。

复权所需事件集合按上海自然日检查：当天首次复权查询同步更新，之后复用；跨日更新失败则复权查询报不可用，已覆盖的未复权历史查询仍可读取。已知历史事件持续保留不代表最新事件集合已经取得。日 K 只允许持久化交易日期早于上海当前日期的记录，当天即使收盘也回源且不入库，次日起按查询需要保存；没有定时入库任务。

已确认含当天边界的请求由服务端内部切分：以该证券缓存已证明的最后一个交易日为界，之前的区间按既有覆盖、缺口与落盘规则处理，之后到请求结束的区间固定回源为当天尾部。尾部中已收盘的部分取得来源证据后照常落盘，因此缓存边界随日期推进，不需要额外探测来源日历；当天部分只在内存参与本次装配与派生，既不落盘也不标记为可复用。两段按原契约返回单一结果，调用方不新增参数也不感知切分。任一段失败即整项失败，不返回只有历史部分的半截结果；缓存未证明窗口内任何交易日，或请求结束日晚于当天时，仍按完整原请求回源。交易日历采用同一切分规则，其尾部已收盘日同样只在取得证据后落盘。此切分只减少重复回源，不改变含当天请求必须回源的能力边界。复权或补齐的含当天日 K 请求在满足本地派生条件时也可切分，使用同次查询的事件视图计算；相关股改或无法安全派生的窗口仍整段回源。2026-10-03 的实际来源对照确认 front 在跨除权日缺行窗口存在随查询起点变化的例外，因此 front 有相关事件时，派生前须验证真实行情与交易日历逐日一致，不能用补齐行证明完整性；该额外检查不扩展到 front_ratio。event_cutoff 无法安全派生时明确失败。具体来源证据及样本边界见设计文档。

历史闭区间 count 查询的前复权支持性以实际选出的缓存后缀起点判断；窗口之外的老股改不应阻断 front/front_ratio 派生。此项复用仍要求所有依赖满足覆盖及时效，不能扩大为跨日断源时使用过期事件集合。

已确认复权日 K 查询的 refresh=true 同时强制刷新本次计算所需的原始日 K 与该证券完整分红除权事件集合，即使事件集合当天已检查也不复用。任一必要来源依赖刷新失败，该证券查询失败并保留旧存储，不用新旧依赖拼成刷新成功；批量其他证券仍按逐项结果处理。来源依赖均成功但持久化失败时，仍遵守返回已校验结果的存储降级规则。

评审确认保留上述严格时效规则：离线承诺仅覆盖范围与有效性均满足要求的已有数据，不承诺跨日断源后的复权历史分析可用。交付范围按当前设计草案完整执行，不采用缩减首期范围、将复权、补齐或财报区间复用延期的方案；文档约定的未知场景回源边界仍然保留。完整交付须包括相应的来源一致性验证，不能将未经验证的本地计算视为已完成。

本轮评审的交付范围、时效、财报隔离与失效、强制刷新依赖、来源返回及启动边界均已逐项确认。来源覆盖证据、复权与补齐一致性等仍须按实际部署验证，不能将设计决策视为已完成实机验证。用户已确认开始实施。实现与实际来源验证的当前边界见设计文档，验收结果不能从 ADR 状态推定。
