# 版本与构建标识

客户端、服务端、Windows 安装包和 QMT 策略统一使用软件发行版本，例如
`0.8.2`。唯一的 Python 版本定义是 `src/qmt_rpyc/version.py`；策略生成器和
发布流程读取该文件，不再手工维护策略版本。安装器的下载版本固定值和文档
示例在发布准备时同步更新。

版本采用 `MAJOR.MINOR.PATCH`：破坏性变更在 1.0 之前升级 MINOR，兼容修复升级
PATCH；预发布使用 `rcN`。已发布版本及标签不可覆盖。未发布构建的修改不需要
每调试一次就增加发行版本。

策略启动日志示例：

```text
QMT_RPYC_BRIDGE ready; version=0.8.2; build=<16位十六进制指纹>; read_only=False
```

`build` 是生成策略内容的 SHA-256 前 16 位，自动计算、可重复生成，用于识别
同一未发布版本下的不同策略内容；它不是另一个版本号，也不是安全签名。
不再使用 `option-chain-fix-2` 等人工修订标签。策略仍为 GBK、兼容 Python 3.6。

公共契约兼容编号和内部桥协议编号仅用于通信校验，不是发行版本。当前
均为 `8`，与 0.8.0 系列对齐。持久数据读取增加 refresh 字段并移除三项板块操作，
客户端、服务端、策略必须配套更新；已发布 0.7.x 的两项编号仍为 7。
在 0.x 阶段，两项兼容编号统一取发行版本的 MINOR（0.7.x 对应 7）。
发布新的 MINOR 时同步调整两项编号，PATCH 修复不调整；不再各自递增。
诊断或错误报告应明确称为“契约兼容编号”或“桥协议兼容编号”，不要将其单独
称为软件版本。用户安装和升级以软件发行版本为准。
